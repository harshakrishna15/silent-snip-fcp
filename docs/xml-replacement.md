# XML project replacement

Interactive Apply now sends one edited project using the current project's name,
original event name/identity, and source library location. Final Cut replaces the
matching item instead of accumulating `— Cutdown ABC123` result projects. The
standalone writer and developer verifier retain their separate-output default;
interactive Apply explicitly selects replacement.

Before sending, Cutdown checks the current timeline against the analyzed baseline,
reveals its original event, rejects an ambiguous browser project name, and saves
`Before-Cuts.fcpxml`, edited XML, settings, and the edit report. Both saved XML files
must still match their prepared bytes at delivery. Recovery XML is not imported
unless the user chooses to restore it, so it adds no browser clutter.

A fresh Apply can accept only the observed matching-library Replace prompt while
the original project and event are current. Final Cut can close that timeline and
show a previous project or an empty timeline. Cutdown then opens the uniquely
named browser result in the original event. The old project's mere visibility is
not evidence of completed replacement. Verification checks the original library
and event, a different host project identity, the complete semantic timeline,
media references, effects, and controller settings before any settings restoration.

Retry Verification never resends XML or confirms replacement. Its saved receipt
retains the replacement destination and binds the first verified host identity.
A failed/cancelled Apply after delivery reports that replacement may already have
happened and points to recovery XML; it does not claim the original is unchanged.
If the browser is elsewhere, select the original event before Retry Verification.

inside this checkout's `Cutdown Integration.fcpbundle`. The library was created
because it was absent here; the other checkout's same-named library was not used
for tests. Generated six-second WAV audio was referenced in place, without copied,

## Validation and limits

- Full Swift suite: 363 tests executed, one skipped, zero failures, with macOS
  media-service access (`full-tests-access.log`). The sandboxed attempt could not
  decode audio through AVFoundation; it is retained separately.
- Final focused suite after the import-readiness regression: 42 tests, zero
  failures (`final-focused-tests.log`). Covers repeated replacement generation,
  wrong destination/original rejection, receipt recovery, missing recovery XML,
  exact dialog matching, cancellation/readiness, and existing copy behavior.
- Audio Controls factory harness passed (`factory-tests.log`).
- Release helper is staged at `build/Candidate/Cutdown.app`; it is not registered
  for live Analyze/Share routes. No installed app bundle was replaced.

Final Cut crashed once while opening the last imported result. The macOS report
recorded stack exhaustion in AppKit text/search-field recursion. The result
survived restart and was opened and exported successfully using Clip → Open Clip.
This observation does not establish a cause or a fix for the host crash.

These are manual host-import probes plus generated-output verification, not a
successful automatic Analyze → Apply → settings-recovery run of the new helper.
That complete flow still needs live verification with matching installed builds.
Existing Audio Unit edits present before this task were preserved. Replacement
changes internal project identity and does not promise preservation of Undo
history. Existing old Cutdown result projects are not deleted by this change.

Apple documents name-based XML item replacement in its
[import workflow](https://developer.apple.com/library/archive/documentation/FinalCutProX/Conceptual/FinalCutProXWorkflowsGuide/Importing/Importing.html).
